================================================================================
BUILD-PROVENANCE - what produced each shipped codebrix_miniaudio binary
================================================================================

One record per binary under
src/CodeBrix.Audio.Engine/Backends/MiniAudio/runtimes/<rid>/native/.

Update this file whenever a binary is replaced. The per-build details it is
copied from are written by the build scripts to
tools/build_native_libraries/output/<rid>/build-info.txt.

All binaries are built from the sources vendored in this folder - miniaudio and
stb_vorbis are in-tree, and no build step reaches outside the repository or
downloads source. See tools/build_native_libraries/README.txt for how to
reproduce any of them, and ../../THIRD-PARTY-NOTICES.txt for licensing.

win-x64, win-arm64, osx-x64, osx-arm64
--------------------------------------------------------------------------------
  These four are still SoundFlow v1.4.1's prebuilt miniaudio binaries, renamed to
  codebrix_miniaudio.* (built from miniaudio @ 80cf7b2, but WITHOUT stb_vorbis).

  CONSEQUENCE: they cannot decode Ogg Vorbis. On those RIDs .ogg playback falls
  back to the managed Vorbis decoder in CodeBrix.Audio, so .ogg still works - it
  just does not use the native path. sf_has_vorbis() is absent from these
  binaries, which is exactly how the managed side detects the situation.

  To replace them, run the scripts in tools/build_native_libraries/windows/ and
  tools/build_native_libraries/macos/ on a Windows x64 machine and an Apple
  Silicon Mac, then record the results here.
